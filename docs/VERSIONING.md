# 版本、提交和里程碑

- main保存可解释、经过相应验证的工程状态。普通改进完成就提交，commit用一句简短简体中文，描述实际变化。
- 一个逻辑改进一个提交；不要把大量无关修改混在一起，也不为凑数量拆碎。失败实验如有知识价值可提交记录。
- 初次导入分层提交当前成果，不伪造过去的Git历史。patch原作者与历史日期保留，当前整理提交使用真实日期。
- 每次改进同步必要的测试证据、状态、限制与回退。工作树应能说明哪些已验证、哪些仍未做。
- 新内核候选用独立LOCALVERSION和模块目录。test06是历史工程编号，不直接等于语义版本。
- 对外用SemVer预发布：首个v0.1.0-alpha.1对应test06。后续可用alpha.2等；核心回退、输入、网络、电源长期验证未完成前不称稳定版。
- tag和Release发布后不移动、不覆盖同名二进制。修正用新版本；若撤回有问题版本，保留原因与哈希记录。
- release清单记录导入后的源码方案提交、上游源码包、补丁/配置和二进制哈希。历史test06构建早于Git，不伪称由导入提交当时构建。
- 不强推、不擅自重写已公开历史；远端有变化先fetch审阅。

里程碑状态与验收标准集中在backlog/ROADMAP.md，日常改进不要求每次都发二进制Release。
